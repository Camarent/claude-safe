# dev: rarely used rules (moved from dev.md; read when the task touches one)

Generated files: if a file you must touch says in its first lines that it is generated (`Generated by ... do not edit`), never edit it by hand: run the generator named in its header and commit the regenerated output. A hand edit fails review. Exception: never run or edit the docs index generator (`docs_index.py`, `cs-docs-index`) or `docs/INDEX.md`: the lead regenerates it. A missing environment binary (a browser, a tool) is `BLOCKED` with the install command, never a WIP commit; never rely on a skipped test (exit 3 is not green).

Regex: any regex on a file is unsafe; assume it matches several places. Anchor it, assert how many places changed (restore if wrong), test with a decoy sharing the value. Parser for JSON/TOML/YAML.

A test that depends on wall-clock time (sleep, a timing threshold, the real `now`) or that is not isolated (it writes a fixed shared file or folder, a fixed port, a shared env or global) is bad design: it shows code that is not separated, and it flakes when tasks run in parallel. It is almost never the right way. Write the code so the clock is passed in (a `now` argument, a fake clock you advance by hand to simulate time passing) and give every test its own temp dir and port. If such a test is truly unavoidable, say so under `Skipped/unchecked:` with the reason: the lead moves it to the project's `gates_merge` (merge gate only). Never loosen a timing threshold or add a retry to make it pass.

Docs: if `docs/ARCHITECTURE.md` exists, read it first, then `docs/modules/<module>.md` and `docs/INDEX.md` to locate code; confirm a cited `path:line` first. A doc contradicting the code: add `DOCS-STALE: <doc> - <what is wrong>` to your reply (outside its length limit); do not edit docs, `docs-writer` owns them.

Never write invisible characters (zero-width, bidi or other) into code, tests or reports. When a failure message shows an escape like \u200b, search the file for it and remove it.

Temp files: never build paths from env vars like $TMPDIR (unset in the sandbox); use `mktemp -d` or the lead's scratchpad; never write outside repo/worktree and scratchpad; no `||` fallback after `cp` to an unchecked path.

Quality run: after your tests are green the driver runs the audit tools (`audit/audit_run.py`: clippy for `.rs`; eslint, knip, jscpd, madge for `.js`/`.mjs`; Python/C++ tools only when the project's `pipeline.json` `quality_tools` lists them; only tools the repo's `AUDIT.md` lists and that are installed) on every file you touched, in every repo you touched, and keeps findings on the lines you changed. It is advisory: if it reports findings you get ONE extra round. Fix the cheap, safe ones inside the files you already changed; leave the rest; no side refactors; in your report name what you skipped and why. You may run a tool yourself first: `cs-qrun -- cs-audit <repo> --only <tool>` (never bare `npx`; it sees your worktree).

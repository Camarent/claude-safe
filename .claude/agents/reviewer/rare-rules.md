# reviewer: rarely used rules (moved from reviewer.md; read when the task touches one)

Regex: any regex in the diff is unsafe; FAIL an edit regex that is not anchored, has no changed-count check, or has no decoy test.

- Tests must not use fixed-depth `../../../` paths to files outside their repo, nor absolute paths to real user data.

- Docs review: verify every claim by grep; reject line-number cites.

Docs: if `docs/ARCHITECTURE.md` exists, read it first, then `docs/modules/<module>.md` and `docs/INDEX.md` to locate code; confirm a cited `path:line` first. A doc contradicting the code: add `DOCS-STALE: <doc> - <what is wrong>` to your reply (outside its length limit); `docs-writer` owns docs. A stale `docs/INDEX.md` alone is `DOCS-STALE: docs/INDEX.md (lead-fix)`: not a FAIL and not a dev failure; the lead regenerates it.

A `docs/INDEX.md` diff is generated by `wt.py commit`: never out of scope, never a finding.

Efficiency: Read files >200 lines only with offset/limit (never whole CONTRACT/TASKS/PLAN-size files; grep the section); do not re-read a file you have. Never `cd <dir>` before git: use `git -C <dir> <args>` (plain `git <args>` when your cwd is already the worktree), e.g. `git -C wt status`. JSON/JSONL: use `jq`, not python/node (see practices/bash.md). Turn budget default 30; at 2/3 of it write state and finish. A long or background command is waited on by ending the turn (the harness re-invokes you on completion): no Monitor, sleep or poll loops, no TaskStop unless asked.

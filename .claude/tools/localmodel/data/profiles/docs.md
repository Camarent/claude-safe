Documentation principles:
- Describe what the code does today, verified by grep or by reading it. Every claim you cannot verify is left out.
- No line-number cites in prose (they rot); name files and functions. Short: a map, not a tutorial.
- Keep the existing document structure and headings; update only the parts the brief names.
- If the docs contradict the code, report `DOCS-STALE: <doc> - <what is wrong>` in your report and do not guess which is right.
